# 设计必要性自检原则

在动手做每一个设计（新卡片、新页面、新功能、新模块、新入口）之前，必须先完成以下自问，不通过则不做：

## 自检清单

1. **必要性**：这个设计有没有必要做？
   - 它解决谁的什么问题？区分"管理者视角"与"被管理者视角"——系统是两类人共用的，单一视角的统计/汇总类功能要降级或后置。
   - 删掉它用户会失去什么？答不上来 = 不做。

2. **重复检查**：其他地方是否已有相同能力？
   - 顶部导航已有 → 不要再做功能菜单卡。
   - 业务模块内已有 → 不要在首页复刻入口。
   - 与现有页面字段/入口冲突的，一律砍掉。

3. **数据真实性**：这个卡片展示的数据有没有真实的功能闭环支撑？
   - 硬编码假入口、无来源的统计数字 = 摆设，不做。
   - 展示什么，必须先有产生它的功能（如"收藏/捷径"必须先有"收藏标签页"动作）。

4. **参考对齐**：有参考系统（如 KMOKE）时，优先还原参考系统的克制设计，不要自己加戏。
   - 参考系统没有的东西，默认不做，除非能通过上面 1-3 的自检。

## 适用范围

- 前端页面设计（首页卡片、导航、工作台）
- 任何"要不要加这个功能/入口/统计"的决策时刻

## 来源

用户（产品经理）于 AIGC 制作管理系统开发过程中确立的协作规则。
