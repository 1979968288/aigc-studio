# 参考系统复刻完整性核对纪律

复刻/核对参考系统（如 KMOKE）时，防止遗漏视觉区域内容的强制纪律。

## 触发场景

- "XX 系统的某区域有什么内容？"（枚举类问题）
- "复刻 XX 页面 / 还原 XX"（复刻类任务）
- 自查"是否还原完整"

## 核对纪律

1. **视觉区域反查法（核心）**：组件名 ≠ 视觉区域。被问"某区域有什么"时，从布局根模板（如 WorkbenchHeader.vue / AppLayout.vue）出发，列出该区域的**全部子节点**逐个深入；禁止从猜测的组件名正向查找。
2. **穷举后才回答**：枚举类问题回答前，对父容器做一次完整扫描（该区域的全部子元素、相关 class 前缀如 `__actions`）；找到第一个答案不许停。
3. **布局模板是真源**：任何布局问题先读布局组合文件再回答；视觉结构以 template 组合关系为准，不以内部分工臆断。
4. **截图终验**：参考系统带截图时（KK 在 public/manual/ 下有首页截图），交付前用截图对照。
5. **复刻前置区域对照清单**：做"100% 复刻"任务时，先产出分区对照清单再动手：

   | 区域 | 参考系统组件 | 我们的实现 | 状态 |
   |---|---|---|---|
   | 顶栏第一行 | ... | ... | ☐ |
   | 标签条+动作组 | ... | ... | ☐ |
   | 内容区卡片 | ... | ... | ☐ |

   每区打勾后才可宣布完成——**没有清单的区域就是会漏的区域**。

## 历史教训

2026-08 复刻 KK 首页时，被问"右上角有什么"只答了消息按钮+用户菜单，漏了标签条右端动作组（刷新/复制链接/标签操作下拉/溢出更多）——根因是按组件名（TopbarUserMenu）正向查找，而非按视觉区域反查；且未穷举 WorkbenchHeader.vue 中 primary 行 slot 嵌套的 WorkbenchTabs。
